# 提交材料清单

对照赛题「四、提交材料」与「五、提交方式」逐项核对。状态在 M9 之前会随进度更新。

## 一、六项必交 + 一项建议

| # | 材料 | 赛题要求 | 现状 | 待办 | 含真实数据 | 敏感处理 |
|---|---|---|---|---|---|---|
| 1 | 项目网站网址 | Qoder Sites 发布，可见范围「任何人都可访问」 | 🚧 | 个人账号发布 → 无痕窗口自测 → 记录 URL | 否 | — |
| 2 | 代码仓库 | 完整源码；公开或对评审开放 | ✅ 本地分支就绪 | 推到自己的 fork/私有仓；私有仓给评审读取权限 | 否 | 仓库内不得有 token |
| 3 | 运行说明 | 环境、依赖版本、部署与接入方式、从安装到启动 | ✅ [RUNBOOK.md](../RUNBOOK.md) | M8 补应用侧步骤与截图 | 否 | 示例值全占位 |

## 二、平台提交五步

1. 登录大赛测试平台，进入 Qoder 赛题入口。
2. 填项目网站网址、代码仓库地址、Qoder 账号 UID。
3. 上传其余材料（开发记录、验证产物、效果材料）。
4. **用浏览器无痕窗口**打开项目网站，确认未登录也能访问。
5. 提交后到评审结束前：不暂停、不删除站点；改内容要重新点「发布」才会生效。

## 三、站点发布检查

- [ ] 使用**个人账号**（企业版账号无法设置公开访问）
- [ ] 可见范围 = 任何人都可访问
- [ ] 无痕窗口可打开，且首屏能看到项目简介
- [ ] 页面含：简介、解决的问题、核心功能、截图或视频、仓库链接、体验入口（或本地运行入口）
- [ ] 有 A/B 对照与审计日志的证据图
- [ ] 无 token、无真实姓名、无本机绝对路径

## 四、红线清单（提交前逐项确认）

- [ ] 仓库内没有 `.env`、`*.db`、`.runtime/`、token、密码
- [ ] 审计日志样例中的 token 已打码
- [ ] 截图里没有终端历史中的凭据、没有他人姓名与联系方式
- [ ] 没有把第三方题库/教材原文当自己的内容提交
- [ ] 提交的 commit 在 `2026-competition-ecosystem` 派生分支上，且改动只在 `qoder/`
- [ ] 私有仓库已给评审开放读取权限
