# 周边去哪儿：步行可达地点推荐

## 目标

把一句自然语言需求转成一次可核对的高德查询：

1. 理解地点类型、步行时间上限、推荐数量、排序偏好。
2. 用高德 **周边搜索** 找候选地点。
3. 对候选逐一查询 **步行路径规划**。
4. 只保留步行时间满足上限的地点，按偏好排序，最多推荐 3 个。
5. 用表格给出名称、地址、步行距离、步行时间和一句有数据依据的推荐理由。

所有地点必须来自高德工具返回结果；所有距离和时间必须来自步行路线结果，不能用直线距离代替。

## 输入解析

从用户输入中提取：

| 字段 | 说明 | 缺省处理 |
| --- | --- | --- |
| `city` | 城市 | 有坐标时可省略 |
| `origin` | 起点坐标，格式 `经度,纬度` | 必须有；若只给地址，先用 `maps_geo` 转坐标 |
| `category` | 咖啡馆、餐厅、公园、便利店等 | 从需求中提取；不明确时先按“附近地点”搜索 |
| `max_walk_min` | 步行时间上限，分钟 | 未给出时不设硬上限，但仍按步行时间排序 |
| `count` | 推荐数量 | 默认 3，最多 3 |
| `preference` | “优先近一点”“安静一点”等 | 近 = 按步行时间升序；其他偏好若无数据依据，不编造 |

把用户要求复述成一个内部约束，例如：

```text
origin=120.123456,30.123456
category=咖啡馆
max_walk_min=15
count=3
preference=步行时间越短越好
```

如果起点坐标缺失、格式不合法，先向用户确认；不要猜坐标。

## 工具调用顺序

### 第 1 步：周边搜索

优先调用：

```text
maps_around_search
```

参数：

```text
keywords = category（可加同义词，如“咖啡馆 咖啡 cafe”）
location = origin（“经度,纬度”）
radius   = 搜索半径，米
offset   = 20
page     = 1
```

半径按步行上限估算，给路线绕行留余量：

```text
有 max_walk_min：radius = clamp(max_walk_min × 90, 500, 5000)
无 max_walk_min：radius = 1500
```

例如 15 分钟 → 约 1350 米。

只使用当前工具 schema 支持的参数；不要伪造参数名。  
如果周边搜索为空，按顺序重试一次：

1. 把关键词换成更宽泛的同义词；
2. 把半径扩大到原来的 1.5 倍（最多 5000 米）。

仍为空时，才考虑用 `maps_text_search` 补充候选；文字搜索结果也必须计算步行路线并满足时间上限，不能直接推荐。

### 第 2 步：整理候选

从返回结果中提取：

```text
id / name / address / location / type / distance
```

结果数组可能位于 `pois`、`data.pois` 或工具直接返回的列表中；先找到实际数组再遍历。  
如果返回的是错误对象（例如包含 `error` 或 `message`），不要把它当成地点列表。

规则：

- 按 `id` 去重；没有 `id` 时按“名称 + 坐标”去重。
- `location` 必须是 `经度,纬度`，否则跳过该候选。
- 周边搜索返回的 `distance` 是直线距离，只能用于预排序，不能作为最终步行距离。
- 优先保留名称或类型与 `category` 相符的地点；明显不符的（例如搜咖啡馆却返回加油站）不进入路线查询。
- 最多取 **12 个**候选做步行路线查询；按直线距离从近到远取，避免无意义的调用。
- 推荐数量最多 3 个，但路线查询可以多于 3 个，以便过滤超时地点后仍有足够结果。

### 第 3 步：查询步行路线

对每个候选调用：

```text
maps_direction_walking
```

参数：

```text
origin      = 用户起点坐标
destination = 候选地点坐标
```

读取返回中的第一条步行方案。不同 MCP 封装的层级可能略有差异，路径数组可能在：

```text
route.paths[0]
paths[0]
data.route.paths[0]
```

字段通常是：

```text
distance   // 米
duration   // 秒
```

先检查实际字段和单位，不要凭字段名猜单位。  
工具返回可能是 JSON 对象，也可能是 JSON 字符串；先解析再读取。  
把 `duration` 统一换算为分钟；把 `distance` 统一换算为米。显示时向上取整到分钟，过滤时使用原始秒数。

判定：

```text
合格 = duration_sec <= max_walk_min × 60
```

没有 `max_walk_min` 时，所有成功返回路线的候选都算合格，但仍按耗时排序。

如果某个候选的步行路线查询失败：

- 不把它列为合格推荐；
- 记录失败原因；
- 继续查询其他候选，不要因为一个失败就放弃全部结果。

### 第 4 步：排序与截断

排序规则：

1. 用户说“优先近一点”或未提偏好：按 `duration_sec` 升序，再按 `distance_m` 升序。
2. 用户明确说“距离近但不想走太久”：仍以步行时间为第一排序键。
3. 用户有其他偏好但没有对应数据：排序仍按步行时间，理由中不要声称“安静”“不排队”“环境好”。

截断：

```text
最终数量 = min(count, 3, 合格候选数)
```

即使 `count` 大于 3，也最多返回 3 个，并在说明中告知“按题目要求最多推荐 3 个”。

## 回答格式

推荐成功时，用简洁表格：

```markdown
**推荐结果（起点：<起点名称或坐标>）**

| # | 地点 | 地址 | 步行距离 | 步行时间 | 推荐理由 |
| --- | --- | --- | --- | --- | --- |
| 1 | <高德返回的名称> | <高德返回的地址> | 约 <N> 米 | 约 <M> 分钟 | <一句有数据依据的理由> |
| 2 | ... | ... | ... | ... | ... |
| 3 | ... | ... | ... | ... | ... |

说明：以上距离和时间为高德步行路线规划结果；营业状态、排队情况和安静程度未核实。
```

推荐理由只使用可核对的信息，例如：

- “步行约 8 分钟，是本次候选中最短的。”
- “步行约 11 分钟，符合 15 分钟以内的要求。”
- “地点类型与‘咖啡馆’相符，步行距离约 700 米。”

不要写：

- “这家店很安静”“不用排队”“现在营业”“环境很好”——除非工具明确返回了对应数据。
- “离你最近”——除非路线结果确实证明它在合格候选中耗时最短。

## 结果不足、无结果、工具异常

### 少于要求数量

如实说明，不要用不符合条件的地点凑数：

```text
15 分钟步行范围内只找到 2 家符合条件的咖啡馆，已全部列出。
第 3 家因步行约 18 分钟超出限制未列入。可以放宽到 20 分钟，或换一个更近的起点。
```

### 没有结果

```text
在以起点为中心约 1350 米的范围内，没有找到符合“咖啡馆”且步行 15 分钟内可达的地点。
可以尝试放宽步行时间、扩大搜索范围，或更换地点类型。
```

### 工具调用失败

```text
高德周边搜索/步行路线查询返回异常：<简短错误>。
在无法核对地点和路线的情况下，我不能编造推荐；请稍后重试，或放宽条件。
```

不要因为结果为空就编造地点、地址、距离或时间。

## 边界与硬性规则

1. **真实数据优先**：名称、地址、坐标、距离、时间必须来自工具结果。
2. **步行时间必须来自路线规划**：不得用 `distance`、直线距离或地图估算代替。
3. **不推荐超时地点**：步行时间超过上限的地点不能出现在合格推荐中。
4. **最多 3 个**：即使用户要求更多，也最多返回 3 个。
5. **每个地点独立**：所有路线都从同一个起点出发，不把推荐串成多站行程。
6. **不编造实时信息**：营业、排队、安静、拥挤、评价等没有工具依据时标注“未核实”或不写。
7. **不泄露密钥**：Skill 中不填写、不索取高德 API Key；运行环境由平台配置。
8. **不重复调用**：同一地点同一起点只查一次步行路线；候选不足时再扩大搜索，不要机械重复相同请求。
9. **失败要说明**：查询失败、结果不足、数据缺失都要简短说明，不能静默伪装成成功。

## 示例流程（仅示意字段，不虚构具体地点）

用户：

```text
我在杭州某地铁站，想找一家咖啡馆，步行不超过 15 分钟，推荐最多 3 家，优先近一点的。
```

内部处理：

```text
origin = 用户提供的坐标
category = 咖啡馆
max_walk_min = 15
count = 3
radius = 1350
```

1. `maps_around_search(keywords="咖啡馆 咖啡", location=origin, radius=1350, offset=20)`
2. 取最多 12 个候选，按直线距离预排序。
3. 对每个候选调用 `maps_direction_walking(origin, poi.location)`。
4. 过滤 `duration <= 900` 秒。
5. 按 `duration` 升序，取前 3 个。
6. 输出表格；若不足 3 个，说明原因。

最终回答只写工具实际返回的名称、地址、距离和时间。
